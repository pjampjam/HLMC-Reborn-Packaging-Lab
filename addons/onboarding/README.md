# Holy Lois Onboarding

Server-only Minecraft 26.3 / Fabric Loader 0.19.5 / Java 25 source. Entry point: `holylois.HolyLois`. Requires Fabric API and EasyAuth 3.4.4. MIT license.

Compile the production Java files against those exact installed APIs, using the compiler output directory for package paths. Exclude `OnboardingTest.class` from the release JAR and put the supplied `fabric.mod.json` at its root. Stop the managed service and take a complete backup before replacing a server JAR.

Version 1.6.0 shows a seven-box streak bar in the daily gift message and a click-to-claim button while EconomyCraft's `/daily` coins are unclaimed (read through `Economy`, which never changes balances), adds `/support` (wallet addresses with click-to-copy; donations never buy anything in game) and awards the Pocket Money, Jackpot, Night Owl and name day achievements.

Version 1.5.0 adds Tab leaderboards, structure discoveries and death coordinates, and removes the quote of the day. With Placeholder API, `%holylois:top title%` and `%holylois:top 1%` to `%holylois:top 3%` show a leaderboard read from the vanilla stats files; each time a player's leaderboard page comes back round, it shows the next category. The first visit to a notable structure is announced to everyone and stored in `world/holylois/discoveries.json`; villages, wells, camps and small ruins are skipped. After a death, the player gets one message with the coordinates and the drop protection time. Latvian name days (`config/holylois-namedays-lv.txt`, Europe/Riga date, from the Latvian State Language Centre's traditional list via the MIT-licensed lv-namedays project) appear as `%holylois:nameday%` and in the welcome message, with a personal greeting when a username starts with one of the day's names. The bot wall reads `config/holylois-botwall.json` (written by the server's `botwall.py` collector, no IPs) for `%holylois:bots_today%`, `%holylois:bots_latest%` and the operator command `/botwall`. Package `holylois-namedays-lv.txt` at the JAR root.

The addon reports EasyAuth state to the paired client helper and handles protected first placement and bedless death respawns. It does not replace EasyAuth credential checks. See TEST-GUIDE.md and TECHNICAL-GUIDE.md.
